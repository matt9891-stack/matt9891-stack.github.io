# Wine Quality Dataset – Exploratory Data Analysis

## 1. Importing and Loading the Data

The first step was to import the required Python libraries and upload the datasets into Google Colab.

python

    from google.colab import files
    files.upload()

    import pandas as pd
    import numpy as np

pandas was used for data manipulation and analysis, while numpy was used for numerical operations. The files.upload() function allows datasets to be uploaded directly into the Google Colab environment.

The red wine dataset was then loaded using:

    df = pd.read_csv('winequality-red.csv', sep=';')
    df_red = pd.DataFrame(df)
    df_red.head()

The sep=';' parameter was required because the dataset uses a semicolon rather than a comma as its delimiter. The data was stored in a Pandas DataFrame, while .head() was used to inspect the first five observations.

The same process was applied to the white wine dataset:

    files.upload()
    
    df2 = pd.read_csv('winequality-white.csv', sep=';')
    df_w = pd.DataFrame(df2)
    df_w.head()

At this stage, both datasets were loaded and inspected. The following analysis focused on the red wine dataset.

## 2. Checking the Dataset Structure and Missing Values

The shape of the dataset was checked using:

    print(df_red.shape)

This returns the number of rows and columns, providing an initial understanding of the dataset size.

The following loop was then used to calculate the percentage of missing values for each variable:

    for col in df_red.columns:
        print(
            f'the column {col} has '
            f'{df_red[col].isnull().sum()/len(df_red[col])*100} % of null values'
        )

For each column, isnull().sum() counts the missing values. This value is divided by the total number of observations and multiplied by 100 to calculate the percentage of missing data.

This is an important initial data-quality check because missing values may affect the reliability of subsequent analysis and modelling.

3. Identifying Data Types

The data type of each variable was also inspected:

    for col in df_red.columns:
        print(f'the column {col} is a {df_red[col].dtype}')

The dtype attribute identifies the type of each variable and helps determine which preprocessing and analysis techniques can be applied.

Understanding data types is particularly important before applying machine learning models, as some algorithms require numerical input.

5. Analysing the Target Variable

The distribution of wine quality scores was investigated using:

    df_red['quality'].value_counts() / len(df_red['quality'])

This calculates the proportion of observations associated with each quality score.

A bar chart was then created:

    (

        kind='bar',
        color='lightblue',
        edgecolor='black'
    )

This visualisation helps identify whether the target variable is evenly distributed or whether some quality categories are more common than others.

Understanding the target distribution is important when developing a predictive model because an uneven distribution may influence model performance.

6. Outlier Identification

Outliers were investigated using both a boxplot and a histogram for the fixed acidity variable:

    fig, axis = plt.subplots(1, 2, figsize=(8, 5))
    
    sns.boxplot(
        df_red['fixed acidity'],
        orient='h',
        ax=axis[0]
    )
    
    sns.histplot(
        df_red['fixed acidity'],
        kde=True,
        ax=axis[1]
    )
    
    plt.tight_layout()

The boxplot provides a visual representation of the spread of the data and can highlight potential outliers. The histogram shows the distribution of the variable and provides additional information about its shape.

The Interquartile Range (IQR) method was then used to identify potential outliers mathematically:

    Q1 = df_red['fixed acidity'].quantile(0.25)
    Q3 = df_red['fixed acidity'].quantile(0.75)

    IQR = Q3 - Q1
    
    lower_bound = Q1 - 1.5 * IQR
    upper_bound = Q3 + 1.5 * IQR

The observations outside these boundaries were then extracted:

    outliers = df_red[
        (df_red['fixed acidity'] < lower_bound) |
        (df_red['fixed acidity'] > upper_bound)
    ]

    print("Outliers in 'fixed acidity':")
    print(outliers)

This allows the potential outliers to be inspected rather than automatically removed. This distinction is important because an outlier is not necessarily an error and may represent a valid observation.

7. Correlation Analysis

Correlation was initially examined using:

    df_red.corr().iloc[:, 0]

This calculates the correlation between the first column and the other numerical variables.

A complete correlation matrix was then visualised:

    plt.figure(figsize=(10, 8))
    
    sns.heatmap(
        df_red.corr(),
        annot=True,
        cmap="viridis",
        linecolor='black',
        linewidth=0.2
    )

The heatmap provides a visual representation of the relationships between numerical variables.

Correlation coefficients range from -1 to +1:

+1 indicates a strong positive linear relationship.
-1 indicates a strong negative linear relationship.
0 indicates little or no linear relationship.

The correlation analysis was used to identify potential multicollinearity between predictor variables.

8. Removing Highly Correlated Predictors

The target variable quality was first separated from the predictors:

    X = df_red.drop(columns=["quality"])

The correlation matrix of the predictors was then converted to absolute values:

    corr_matrix = X.corr().abs()

Absolute values were used because both strong positive and strong negative correlations can indicate multicollinearity.

To avoid checking the same pair of variables twice, only the upper triangle of the correlation matrix was selected:

    upper_tri = corr_matrix.where(
        np.triu(
            np.ones(corr_matrix.shape),
            k=1
        ).astype(bool)
    )

A correlation threshold of 0.80 was then applied:

    threshold = 0.80
    
    to_drop_multicollinear = [
        column
        for column in upper_tri.columns
        if any(upper_tri[column] > threshold)
    ]

Variables with an absolute correlation greater than 0.80 with another predictor were identified as potential multicollinearity problems.

The selected variables were then removed:

    df_reduced = df_red.drop(
        columns=to_drop_multicollinear
    )

The purpose of this step was to reduce redundancy between predictors and potentially improve the stability and interpretability of models that are sensitive to multicollinearity.

9. Identifying Predictors with Low Correlation to the Target

The relationship between each predictor and the target variable was then calculated:

    target_corr = X.corrwith(
        df_red["quality"]
    ).abs()

This measures the correlation between each predictor and quality.

A minimum threshold of 0.05 was selected:

    min_corr_threshold = 0.05
    
    to_drop_low_target = target_corr[
        target_corr < min_corr_threshold
    ].index.tolist()

Variables with an absolute correlation below 0.05 were identified as having a very weak linear relationship with the target.

These variables were selected for potential removal:

    print(
        "Features dropped due to low correlation with target:",
        to_drop_low_target
    )

However, this step should be interpreted carefully. A low correlation does not necessarily mean that a variable has no predictive value. Correlation measures linear relationships, while some machine learning models can identify non-linear relationships.

Critical Reflection

The analysis provided an initial understanding of the structure, quality and relationships within the red wine dataset. The use of descriptive statistics, visualisations, outlier analysis and correlation analysis helped identify potential issues before modelling.

However, correlation-based feature selection has limitations. In particular, removing variables based on a low correlation with the target may remove features that have non-linear or interaction-based relationships with wine quality. This is especially relevant when applying tree-based machine learning models, which can capture relationships that Pearson correlation does not identify.

Therefore, the feature-selection process should not be considered definitive. Further modelling and validation would be required to determine whether removing these variables actually improves predictive performance.
